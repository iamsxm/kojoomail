# Windows 安装器的进程清理

`src-tauri/windows/hooks.nsh` 同时用于 NSIS 安装和卸载。原来的实现执行
`taskkill /F /T /IM ...` 后固定等待 500 ms，没有检查结束结果或文件占用。
如果命令失败，或 MCP 客户端在覆盖文件前重启代理，安装器仍会进入解压阶段。

现在按当前安装目录处理 `kojoomail.exe`、历史名称 `Kojoo Mail.exe` 和
`kojoomail-mcp.exe`：

1. 将旧文件临时改名为 `*.kojoomail-install-old`，使外部客户端暂时无法通过原路径重新启动旧代理。
2. 通过 Windows Restart Manager 按文件定位并关闭占用进程，不按全局进程名结束其他安装目录的实例，也不结束整个子进程树。
3. 轮询打开旧文件的写入句柄，确认映像占用已经解除，才允许 NSIS 解压文件。轮询最多等待 3 秒；系统自身的关闭操作另有等待时间。
4. 准备失败时恢复原文件名，在解压前停止并返回退出码 2。交互安装会显示失败路径和处理提示。
5. 成功解压后删除旧文件。下次安装能够处理上次中断留下的旧文件。

此过程不依赖 PATH、taskkill 或 PowerShell。Windows 权限仍适用：如果目标进程以管理员身份运行，普通权限安装器可能无法结束它，安装器会停止并提示使用管理员权限重试。

## 验证

Tauri 下载 NSIS 工具后运行：

```powershell
./tests/windows-installer.ps1
# 指定其他 NSIS 编译器：
./tests/windows-installer.ps1 -MakeNsis 'C:\Program Files (x86)\NSIS\makensis.exe'
```

测试使用系统 `ping.exe` 的隔离副本模拟主程序和多个 MCP 进程，在临时目录编译、运行真实 NSIS 安装器和卸载器；不写产品注册表，不操作真实安装目录。覆盖：

- 全新安装、带空格的路径、空 PATH。
- 运行中的主程序、历史程序名称、多个 MCP 进程。
- 保留另一个安装目录的同名进程。
- 解压中断留下的旧文件，以及旧文件和新文件同时存在的恢复。
- 文件不可写时停止解压、恢复原文件，以及解除阻碍后的重试。
- 客户端在断线后反复重新启动代理。
- 卸载前关闭进程并删除旧文件。

`build-desktop.yml` 在 Windows 打包完成后执行这套测试，失败会阻止收集和发布产物。测试验证安装器的文件替换机制；真实 MCP 协议和邮件收发由其他测试覆盖。

修改安装器源码不会改变已经下载或公开发布的安装包，需要重新构建，并通过新版本发布分发。
